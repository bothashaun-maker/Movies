# Existing image migration

Do not delete images or overwrite originals. An application's MIT badge never resolved pretrained-weight rights, but that also does not prove every image in your library must be redone.

Run `python audit_outputs.py /path/to/saved/images --report /path/to/review.json`. It reads PNG embedded metadata and JSON manifests without modifying them. InSwapper/buffalo_l/old StudioFaceSwap graphs are flagged for restricted-face-pipeline review. Juggernaut/FLUX3 are flagged for terms review. Missing metadata remains unknown; a v7 marker only records that profile, not a legal clearance or proof about upstream inputs. Metadata can be incomplete or altered. The scanner does not infer what a photo looks like or who it depicts.

For affected research-weight swaps, preserve the old result for comparison, obtain the **clean pre-swap target** and original identity photo, and recreate with the new methods, or obtain written model-owner permission covering the old workflow and your intended use. Applying v7 on top of an old swapped result does not erase its history or confer a retroactive license. A JJP master.png may already contain the swap. If no clean target survives, regenerate that scene with v7 before editing identity.

Existing Real-ESRGAN/SeedVR2-only work does not need redoing solely because the old face stack was unsuitable. Juggernaut's extra terms and FLUX3's exact accepted custom terms need their own review; do not blanket-label all their outputs forbidden. Audit approved-cast photos and source scenes too. Keep rights records separate from model manifests.

Build the new create_edit and finish packs. Attach existing packs only as sources of hash-matching retained upscalers; no InsightFace files are loaded by v7. Never delete old private datasets just to migrate. Use a fresh imported v7 Kaggle notebook so the previous startup cell and installed custom nodes cannot remain active.
